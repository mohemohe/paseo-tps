# Paseo TPS

エージェントのトークン生成速度を計測し、composer の上部に pill として表示する
Paseo プラグインです。

- pill は `42.3 TPS` のように表示します（計測前は `-- TPS`）。
- マウスホバーでツールチップに TTFT と TPS の両方を表示します
  （例: `TTFT 1.23s · TPS 42.3 · click to reset`）。
- クリックすると計測値をリセットします。
- ストリーミング中はリアルタイムで更新します。

## 計測の定義

| 指標     | 定義                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| **TTFT** | 生成セグメントの開始から最初の出力トークンまでの時間。                                 |
| **TPS**  | 最初の出力トークンからターン終了までの生成時間で割った、出力トークン数。               |

ターンは**セグメント**単位で計測します。セグメントは必ずユーザーの入力、またはツール
コールの終了から始まり、ツールコールの開始かターンの終了で閉じます。ツールコールの
時間は生成時間に含めないため、ツールを複数回呼ぶターンでもモデルの実際のストリーミング
速度が表示されます。TTFT は最初のトークンを出したセグメントを基準に計測します
（ユーザーの入力から、またはツールの後に応答する場合はそのツール終了から）。

## トークン数の見積もり

Paseo はプラグインにストリーミング中のトークン数を渡しません
（`usage_updated` はクライアントに届きません）。そのため、デーモンがストリーミングする
テキストから [`tokenx`](https://www.npmjs.com/package/tokenx) で出力トークンを見積もります。
tokenx は OpenAI の `o200k_base` を基準に調整された純 JS のヒューリスティック推定器です
（平均 95% 程度の精度、CJK・多言語対応）。`assistant_message` と `reasoning` の両方を数え、
ツールコールの引数は数えません。

ターン完了時にプロバイダが正の `turn_completed.usage.outputTokens` を返す場合、その値で
見積もりを補正するため、確定値はプロバイダのカウントと一致します。ストリーミング中の値は
推定のままです。

## 設定

**Settings → Plugins → paseo-tps → Display** を開きます。サイドバーには項目を追加せず、
設定はプラグイン一覧からのみ遷移できます。

- **Correct the final rate with the provider's usage**（既定: オン）: オンにすると、完了した
  ターンは推定値ではなくプロバイダが報告した出力トークン数を使います。プロバイダが最後の
  リクエスト分しか返さず確定値が低すぎるように見える場合はオフにしてください。

## 保持すべき挙動

- 計測は必ずユーザーの入力、またはツールコールの終了から開始する。
- ツールコールの時間と、ツール実行中にストリーミングされたテキストは除外する。
- 並列ツールコールは、すべて終了するまで計測を停止したままにする。
- ターンは `turn_completed` / `turn_failed` / `turn_canceled` で終了し、確定した値は
  次のターンまたはリセットまで pill に残る。
- 完了したターンが正の `usage.outputTokens` を返す場合はその値で確定値を補正し、
  それ以外は推定値を用いる。
- pill はワークスペースを持つアーカイブされていないアクティブなエージェントごとに登録し、
  エージェントのアーカイブ時やプラグインのアンロード時に削除する。

## インストール

```sh
paseo plugin install github:mohemohe/paseo-tps
paseo plugin update paseo-tps   # 以降の更新
```

Paseo 0.11.0 以降が必要です。Git ソースには `build` ステップ（`npm ci --omit=dev`）を
宣言しているため、インストール・更新時にデーモンが依存パッケージ `tokenx` を導入します。

## 開発

```sh
npm install
npm run check   # tsc --noEmit && vitest run
paseo plugin install .          # 作業中のコピーをインストール
paseo plugin reload paseo-tps   # 編集後
```

クライアントエントリが pill と Display 設定画面を登録し、サーバーエントリは設定
ドキュメントの登録のみを行います。Paseo はプラグインのソースを直接読み込むため、
ビルド手順はありません。
